This iteration extends the existing Next.js/FastAPI/SQLAlchemy application. Baseline before edits: 39 backend tests passed; TypeScript, ESLint and production build passed. Existing accounts and database architecture were preserved. ## Spatial interface and performance update

- The full navigation shell renders before session verification. Temporary service errors keep the interface and expose Retry; only an actual 401 redirects to sign-in. The old blank "Opening your workspace" screen is removed.
- The dashboard contains a real revision-pinned code atlas, direct source/PR/search actions and a simpler workflow. The shared 3D renderer now uses layered source modules, a dimensional core, curved relationships, ground grid, selection, pointer orbit, zoom, reset and fullscreen. Reduced-motion/no-WebGL users receive an interactive isometric SVG map and keyboard module controls. Rendering runs on demand with a bounded pixel ratio; below-fold scenes load when approaching the viewport. No remote font request blocks styling.
- Session/user/membership validation is one SQL read; workspace/preferences are one more. Repository and analysis list counts use grouped reads rather than loading child records per row. Tests assert the two-read bootstrap and immediate session revocation.
- Short-lived (15-second) tab-memory reads coalesce concurrent requests and make return navigation immediate while fresh. Mutations, logout and 401 clear cached data; nothing is persisted to browser storage.
- Repository indexing fetches four pinned files at a time over reused GitHub HTTP connections. Actual source-byte bounds and deterministic order are tested despite concurrent completion and inaccurate upstream sizes.
- Synchronous database polling/maintenance runs in a worker thread rather than blocking HTTP's event loop. Cleanup runs once per minute instead of every two seconds; atomic job claims, lease recovery and bounded retries remain in place.
- Both Render services deployed commit 5d61f26 successfully; GitHub Actions run 6 passed. Two warm production /me requests improved from 5.982 and 5.017 seconds (mean 5.50) to 1.257 and 1.229 seconds (mean 1.24), about 77% faster in this small workstation sample. Other measured workspace endpoints returned in 1.21–1.50 seconds. These are warm request timings, not an availability guarantee; Render Free still sleeps after inactivity. Production registration, password login/logout, secure cookies, origin/CSRF guards, preferences and disposable-account cleanup passed again. The owner repository refreshed successfully to 5d61f26 with 60 revision-pinned files.

## External configuration and remaining limits

Both Render Free services are live, with all four migrations applied to the dedicated Mumbai Supabase Free project; its Data API is disabled. Direct and proxied readiness passed. Production registration, password login/logout, secure cookies, origin/CSRF rejection, persisted preferences and disposable-account deletion passed. Contact submission returned a committed record. Google OAuth is published with only basic identity scopes; Google and GitHub sign-in access the same owner workspace. The read-only GitHub App is installed only on `Lingu17/intervexa`, attached to that workspace, and discovers branches/synchronizes PRs. A real signed push webhook returned HTTP 200. A dedicated private fixture repository now has two open PRs; production synchronization and static interaction analysis passed. See the real GitHub integration report. A real index saved 60 revision-pinned files and renders its architecture. A frontend 30-second proxy timeout hid the initial successful indexing response; the proxy deadline is extended to cover the backend's 180-second limit, and errors clear stale progress. AI keys and the separate Linux runner remain unconfigured. See [deployment](deployment.md) and [runner requirements](../runner/README.md).

This remains an early-access implementation, not a completed production SaaS. Email verification/recovery delivery, a distributed/proxy-aware limiter, operational backups/monitoring, independent security/legal review, resolved cross-language and dynamic dependency graphs, SQL migration semantics, higher-order combinations and private/dependency-installing/multi-framework runners remain unfinished. Password recovery is an honest unavailable state rather than a fake send operation. Contact review requires the deployment operator's database access; no dashboard is advertised.

Personal workspaces currently have one owner. Nonsecret AI preferences are scoped to that user and workspace; a future multi-workspace UI needs further schema/workspace-selection work. Account export contains the latest 500 retained analysis snapshots and their findings/tests, not every database record or backup. Retention cleanup depends on the API worker being awake. In-memory limits are per-process; local frontend proxy traffic shares loopback buckets.

Vercel Hobby is unsuitable for a commercial SaaS deployment. Render free services sleep and share hours; Supabase free storage and inactivity limits apply. These are evaluation choices, not availability guarantees. Sites cannot run the Python API/rootless Linux runner, so no disconnected static version was published.
